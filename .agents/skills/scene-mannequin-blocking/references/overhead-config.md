# 偏俯视／顶视站位图：流程与配置

用于“来个俯视图”“后面的人看不清”“把已有站位图从上面看”。原照片合成仍用 `render_mannequins.py`；本模式用 `render_overhead.py` 建立近似三维布局，换相机渲染。无需图片生成 API 或 Blender，仅依赖 Pillow、numpy，以及同目录的核心渲染器。

## 从输入图到俯视图

1. 打开用户指定的人偶图或场景图，读取对应场次。记录该版本每人的姓名、颜色、脚下区域、与家具的关系、朝向、动作时刻。已有 JSON 可辅助辨认，不可用另一版站位代替指定图。
2. 统一地面坐标：`x` 沿原图向右，`y` 沿场景向深处，`z` 向上；地面是 `z=0`。单位为一致的近似模型尺度，成人站立模型约1.8单位。原图 `foot=[u,v]` 是像素比例，不能直接作为三维位置，也不能仅拉伸照片伪造俯视角。
3. 从桌腿、地面边界和操作面估计家具与脚位，配置长宽、高度和相对距离。保留原有走道、炉列、案台、水槽、小桌；同一家具不能因看不见就另造一套位置。仅建模辨认空间所需的物体；未知区域简化，不宣称恢复了照片外的信息。
4. 将人物放到可用地面或对应座椅上，复用原颜色与动作。多人站位不因抬机位而改变。坐姿用 `seated=true`，同时降低躯干与弯腿；儿童用 `scale` 缩小后对齐座面，可用 `position.z` 补足座高。不要单改腿来假装坐姿。
5. 起始使用55°偏俯视、-60°方位角；需要时调整相机，90°为正顶视。自动取景包含所有模型，预留标签边距。减少遮挡优先抬机位或调整方位角；墙可做低墙／剖开示意，不能为露全身体移动剧情人物和家具。
6. 渲染、打开图片，与输入图核对人数、颜色、前后关系、操作侧、手与目标接触、坐姿座高及遮挡。标签放在空白处，必要时改 `label_xy`；画面应完整、可辨。换时刻另存一份配置，不把多个状态叠到同一场景。

原图中锅盖、凳子等状态默认保持；若与分镜不同，交付时指出。俯视图是空间调度示意，不替代完成道具状态编辑的分镜首帧。

## 调用与示例

从项目根目录运行，将 `python` 替换为含 Pillow、numpy 的解释器；缺包时优先查找 `load_workspace_dependencies` 返回的预装环境。

```sh
python .agents/skills/scene-mannequin-blocking/scripts/render_overhead.py \
  --config /path/to/project/overhead.json
```

可参考 [可运行配置示例](overhead-example.json)。这是说明格式的布局，不是默认场景或人数。将配置复制到当前项目并按输入图改写，`output_prefix` 指向项目资产目录。快速查看示例时显式指定输出，避免将图片写进技能目录：

```sh
python .agents/skills/scene-mannequin-blocking/scripts/render_overhead.py \
  --config .agents/skills/scene-mannequin-blocking/references/overhead-example.json \
  --output-prefix tmp/scene-mannequins/overhead-example
```

输出 `<前缀>_标注.png` 和 `<前缀>_无字.png`。无字版无标题、姓名、引线或箭头。路径相对配置文件解析；命令行 `--output-prefix` 相对当前执行目录解析。

- `--check-only`：检查配置，不渲染、不写文件。
- `--clean-only`：只生成无字版，无需字体。
- `--output-prefix`：另存新版本，适合调整相机或标签。
- 已有输出默认拒绝覆盖，只有明确需要替换时使用 `--overwrite`。

## 顶层配置

| 字段 | 用法 |
| --- | --- |
| `output_prefix` | 必填，输出文件前缀，不含后缀 |
| `source_image` | 可选，输入图路径，仅记录依据并检查存在，不用于自动推断三维场景 |
| `canvas` | 默认 `[2048,1536]`；与原图不同的画幅可用于空间示意 |
| `supersample` | 1、2、3，默认2 |
| `camera.elevation_degrees` | 10—90，默认55；从水平视线向上抬高，90为顶视 |
| `camera.azimuth_degrees` | 绕地面原点的相机方位，默认-60；只改变观察方向，不移动场景 |
| `margins` | `[左,上,右,下]` 像素边距，默认 `[220,210,260,180]`；小画幅需同步缩小 |
| `floor.bounds` | 必填 `[xmin,ymin,xmax,ymax]`，近似地面范围 |
| `floor.color`、`floor.tile_size` | 地面色、可选砖块大小 `[宽,深]`，纹理仅为示意 |
| `objects` | 家具与道具数组，可以为空；形体见下表 |
| `people` | 必填、非空人物数组，人数不限 |
| `tools` | 可选，手持杆状工具，连接手到世界坐标目标 |
| `notes` | 可选环境标注，元素为 `text`、三维 `target`、归一化 `label_xy` |
| `title`、`subtitle`、`footer` | 仅用于标注版；说明是近似空间还原 |
| `font`、`background` | 可选字体路径和背景色；字体自动发现规则与原图渲染器相同 |

## 家具与道具

所有形体使用同一三维相机、深度缓冲与光照。共同可选 `color`，`yaw_degrees` 绕自身锚点旋转；角度正方向将局部+x转向世界+y。

| `type` | 必填几何参数与锚点 |
| --- | --- |
| `box` | `position` 为局部左前下角，`size=[宽,深,高]`；用于墙、台面、木块 |
| `table`、`stool`、`shelf`、`sink` | 同上，生成腿与台面、座面、隔层或凹盆；尺寸各分量至少0.15 |
| `stove` | `position` 为炉底中心，近似固定大小；`vessel` 为 `pan`、`covered_pot` 或 `empty`，默认 `pan`；不自动推断锅状态 |
| `cylinder` | `position` 为底面中心，`radius`、`height` 为正数 |
| `ellipsoid` | `position` 为中心，`radii=[x半径,y半径,z半径]` |
| `segment` | `start`、`end` 为不同的三维端点，`radius` 为正数；可作龙头或把手 |

不合适的复杂家具可由多个基础形体组合；不要改动通用渲染器来硬编码某个场次。所有尺寸为近似模型单位，不是真实测量。

## 人物、坐姿与工具

| 字段 | 用法 |
| --- | --- |
| `id`、`name`、`color` | 唯一标识、姓名、识别色；沿用用户指定图 |
| `position` | 必填世界坐标 `[x,y,z]`，立姿默认脚下锚点，坐姿默认地面锚点 |
| `scale` | 默认1，整体同比缩放；儿童按需要缩小，不以照片远近造成的人像尺寸直接判断实际身高 |
| `pose` | `stand`、`talk`、`stir`、`place`、`wash` |
| `seated` | 默认false；true时躯干下移0.43、腿弯曲，髋高约0.51×scale，检查与座面一致 |
| `yaw_degrees` | 绕人物脚下整体转身；将局部+x转向世界+y为正90° |
| `facing`、`head_yaw_degrees` | 先沿用原图渲染器的局部镜像与头朝向，再叠加整体转身；`facing=right`会镜像局部x |
| `hat`、`bag` | 可选黑帽、手持绿色菜袋示意，不代表最终外貌或服装 |
| `arms`、`legs` | `[2,3,3]` 自定义关节点；详见 [原图配置](render-config.md)。坐姿的arms仍按立姿局部高度填写，脚本再下移0.43；自定义legs直接以坐姿地面为基准 |
| `label`、`label_xy` | 简短说明、归一化标签左上角；无字版不显示 |

`tools` 示例：

```json
{"person":"a","hand":0,"target":[0.45,1.44,0.85],"radius":0.012,"color":"#858577","bowl":true}
```

这里 `target` 是世界坐标，原图合成的工具 `target` 是二维像素比例，两种配置不能混用。手的位置在身体镜像、转身、缩放后计算；工具与家具正常互相遮挡。

## 交付

保留标注版、无字版与可复现 JSON 配置；附上“近似空间还原的站位示意”及原图与分镜重要状态差异。将俯视图交给后续生成模型时，原图继续锁定环境、光线与成片机位；俯视图补充人物关系，除非用户明确要拍俯视镜头，不把其观察角度自动当成成片机位。

> 仅参考人偶的站位、身体朝向、动作与远近比例；人偶替换为对应角色，外貌服装以角色参考图为准；不生成示意人偶、颜色标识或标签。
